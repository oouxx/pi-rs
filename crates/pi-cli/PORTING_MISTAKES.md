# PORTING_MISTAKES.md — pi-cli

对齐检查中修复的真回归 bug（非有意偏差）。"根因模式"尽量归到
`PORTING.md` 的"高危陷阱"表分类。

| # | 位置 | 现象 | 根因模式 | 修复方式 |
|---|------|------|---------|---------|
| 1 | `run.rs:resolve_session_opts` | 默认运行 `pi-rs`（无 `--no-session`/`--session` 等）时 `persist_session=false`，会话变成内存会话、从不落盘；退出时 `formatResumeCommand` 因此永远返回 `None`，`To resume this session:` 提示从不出现。 | **用"原始参数"推断"解析后的模式"**：`resolve_session_opts` 拿 `args.mode`（默认 `OutputMode::Text`）判断是否 interactive，而真正的模式由 `resolve_app_mode`（`Text` + TTY → `Interactive`）决定。TS 侧 `createSessionManager` 在所有非 `--no-session` 路径都持久化，与 mode 无关。 | `persist_session = !args.no_session`（对齐 TS）；补单测 `default_args_persist_session` / `no_session_disables_persistence`，以及端到端持久化链测试 `assistant_message_persists_file_and_enables_resume_command`。 |
| 2 | `core/sdk.rs:create_agent_session`（默认 session dir） | 新建会话的默认目录用 `SessionManager::default_session_dir` = `{agent_dir}/sessions`（裸根目录），而 `uses_default_session_dir()` / `SessionManager::list()` 用 `config::get_default_session_dir` = `sessions/--<encoded-cwd>--`。两者永远不相等，导致：①resume 提示总是多打 `--session-dir`；②按 id 查找会话时本地列表找不到（列的是 encoded 子目录，会话却建在根目录）。 | **同一语义有两个不同实现**：TS 只有 `getDefaultSessionDir`，Rust 移植时分裂出 `SessionManager::default_session_dir`（返回 sessions 根），创建与比较各用一个。 | sdk 默认目录改用 `config::get_default_session_dir(&cwd, Some(&agent_dir))`，与比较/列目录一致；补测试 `assistant_message_persists_file_and_enables_resume_command` + pty 实测 resume 提示为 `pi-rs --session <id>`（无 `--session-dir`）。 |
| 3 | `run.rs:resolve_session_opts`（`--session` / `--fork` 解析） | 传入的 session id 在本地列表匹配不到时，`.or_else(|| Some(s.to_string()))` 把 id 当作**文件路径**交给 `SessionManager::new`；路径不存在 → `new_session()` → **静默新建一个会话**，看起来就是"resume 没生效"。 | **静默 fallback 掩盖查找失败**：TS `resolveSessionPath` 匹配不到时返回 `not_found` 并报 `No session found matching '<arg>'`，从不把 id 当路径。 | 新增 `resolve_session_id`（精确→前缀，找不到返回 `Err`）与 `is_session_path_arg`（仅含 `/`/`\`/`.jsonl` 当路径）；`resolve_session_opts` 改返回 `Result`，两个调用方打印错误并 `EXIT_FAILURE`；补单测 `unknown_session_id_errors_instead_of_creating_session`、`session_path_args_are_detected`。 |
| 4 | `args.rs:parse_args`（`--mode`） | 未知 `--mode` 值（或缺失值）静默回落成 `text`，用户以为切了模式却没切；TS #9045 改为报错并非零退出 | 静默 fallback（`?? default` 掩盖异常） | `CliArgs` 增 `invalid_mode`；`--mode` 未知/缺失时记录，`run.rs` 打印 `Error:` 并 `EXIT_FAILURE`；补 `test_parse_invalid_mode_records_error` |
| 5 | `run.rs:handle_config_command` | `pi config <key> <value>` 只打印 `Setting …` 就返回成功，**什么都没写**；`config` 也没有 `-l/--local` 与未知 flag 的诊断 | 占位实现留在了生产路径上（`// TODO: wire up actual settings persistence`），成功退出码把「没做」包装成「做了」 | 改为真落盘：`model`/`provider`/`theme`/`thinking_level` 走 `SettingsManager` 的类型化 setter（`-l/--local` 走 `set_project`），未知 key / 未知 flag / 参数个数错误分别报错并退出 1，成功打印 `Set <key> = <value> (global\|project)`；命中仍是 TS `selectConfig` 面板的替代形式（见 `DEVIATIONS.md` #24） |
| 6 | `run.rs:handle_subcommand` + `update.rs:parse_update_options` | `pi update --models` 报 `unknown option`，`pi update --self` / `pi update self\|pi` 同样被拒；TS 这三者分别刷新模型目录 / 指定更新二进制（默认） | 只实现了自更新的 `--check/--force`，没把 TS `update` 的其它目标接上（`pi refresh` 已有等价实现） | `--models` 转调已有的 `refresh` 路径；`--self`/`self`/`pi` 接受为「默认目标」；补 `parse_accepts_self_aliases`。2026-11-10 起 `--extensions`/`--extension`/位置参数明确报错：pi-rs 不支持包管理 |
| 7 | `list_models.rs:list_models` | 搜索无命中时写 stderr 并 exit 1（TS 是 stdout + exit 0）；搜索用 `contains` 覆盖 id/provider/**name**（TS 是 `fuzzyFilter(..., \`${provider} ${id}\`)`）；表格把 context/max-out 右对齐且多打一条分隔线（TS 全列 `padEnd`、无分隔线）；无模型时只打印一行（TS 带 `/login` 与 docs 路径） | 表格与搜索是本地重写而不是照抄 TS 的 `listModels`；退出码语义（「查不到」不是错误）也被写成失败 | 无命中改 stdout + 成功退出并使用 TS 文案 `No models matching "…"`；搜索改用 pi-tui 的 `fuzzy_filter_indices`（经 `pi_coding_agent::pi_tui` 重导出，避免第三份 fuzzy 副本）；表格全列左对齐并去掉分隔线；无模型走 `format_no_models_available_message`；补/改 3 个用例 |
| 8 | `list_models.rs:list_models` / `format_token_count` | 仍用 `get_models()` 列出所有目录模型；token 格式用 `fract() < 0.05` 判定整数（`1_048_576` 输出 `1M`，TS `toFixed(1)` 是 `1.0M`） | 漏了 TS `getAvailable()` 的 auth 过滤；把"接近整数"当成"整数" | 改用 `get_available()`；整数判定改 `fract() == 0.0`，非整数用 `to_fixed(...,1)`；补 `1_040_000`/`1_048_576`/`1_250_000` 断言 |
| 10 | `list_models.rs` 排序 | provider/id 用 Rust 字节序；TS `localeCompare` 先按大小写折叠的语言序比较 | 少了一层大小写不敏感比较 | 新增 `locale_cmp`（小写比较后再按原拼写 tie-break） |
