# DEVIATIONS.md — pi-coding-agent RPC Mode

This file documents intentional deviations from the TypeScript original
(`packages/coding-agent/src/modes/rpc/rpc-mode.ts`) in the Rust port.

| # | 位置 (ファイル:行/関数) | 原 TS 行为 | Rust 实际行为 | 修改原因 | 确认状态 |
|---|------------------------|-----------|--------------|---------|---------|
| 1 | `handler.rs:Prompt` | TS emits `success(id, "prompt")` via `preflightResult` callback after preflight succeeds, or `error(id, "prompt", msg)` on failure. | Rust now emits `success(id, "prompt")` via the same preflight mechanism: `PromptOptions.preflight_result` is called with `true` when the prompt is accepted (queued or about to run) and `false` on preflight rejection; the RPC handler sends the success response on `true` and the error only if preflight never succeeded. | **Reversed**: `AgentSession::prompt()` now supports a `preflight_result` callback (matching TS `PromptOptions.preflightResult`), so the success response timing matches TS (prompt accepted, not run completed). | 已回退 (was 已确认保留) |
| 2 | `handler.rs:NewSession` | TS calls `rebindSession()` after successful new session to re-subscribe events and re-bind extensions. | Rust now mirrors this: `new_session` emits `session_start` (reason "new") via `emit_session_start()` and the RPC main loop re-subscribes session events (matching TS `rebindSession`). | **Reversed**: rebind behavior now matches TS. | 已回退 (was 已确认保留) |
| 3 | `handler.rs:Fork` | TS returns `{text: string, cancelled: boolean}` where `text` is the selected text from the fork result. | Rust now returns `{text: <selected user-message text>, cancelled: false}` — the selected text is extracted from the forked entry via `session_manager.get_entry(entry_id)` (matching TS `extractUserMessageText`). | **Reversed**: the `text` field is now populated from the forked entry's user message content. | 已回退 (was 已确认保留) |
| 4 | `handler.rs:SwitchSession` | TS calls `rebindSession()` after successful switch. | Rust now mirrors this: `switch_session` emits `session_start` (reason "resume") via `emit_session_start()` and the RPC main loop re-subscribes session events. | **Reversed**: rebind behavior now matches TS. | 已回退 (was 已确认保留) |
| 5 | `handler.rs:GetCommands` | TS queries `extensionRunner.getRegisteredCommands()`, `promptTemplates`, and `resourceLoader.getSkills()`. | Rust now queries extension commands via `resolve_extension_commands(registry.commands())`, `prompt_templates()`, and `resource_loader().skills` — matching the TS order (extension → prompt → skill). | **Reversed**: extension commands are now included. `ResolvedCommand.source_info` changed from `Option<SourceInfo>` to `SourceInfo` to carry provenance. | 已回退 (was 已确认保留) |
| 6 | `mod.rs` | TS handles `extension_ui_response` type on stdin to resolve pending extension UI dialogs (select/confirm/input/editor). | Rust handles `extension_ui_response` type on stdin via `pending_extension_requests` map in `RpcHandlerState`. Extensions are now enabled in RPC mode (`enable_extensions: true`), matching TS behavior. | **Reversed**: extensions are now enabled in RPC mode. | 已回退 (was 已确认保留) |
| 7 | `handler.rs:Prompt` | TS passes `images` and `streamingBehavior` to `session.prompt()`. | Rust passes `images` and `streaming_behavior` through `PromptOptions`. | Functionally equivalent — the Rust `PromptOptions` struct supports both fields. | 已确认保留 |
| 8 | `handler.rs:Bash` | TS passes `excludeFromContext` to `session.executeBash()`. | Rust passes `exclude_from_context` through `execute_bash()` to `record_bash_result()`. | Implemented: `execute_bash()` now accepts `exclude_from_context: Option<bool>` and calls `record_bash_result()` internally, matching TS behavior. | 已确认保留 |
| 9 | `agent_session.rs:set_model` / `cycle_model` | TS `_emitModelSelect()` only calls `this._extensionRunner.emit(...)` — model_select is sent to extension runner only, NOT through session's `subscribe` mechanism | Rust was calling `self._emit(AgentSessionEvent::ModelSelect { ... })` which sends model_select to all session subscribers (including RPC mode's event listener) | TS only sends model_select to extension runner, not as a session event. RPC clients should not receive model_select events. Fixed by removing the `_emit` call, keeping only `dispatch_model_select` to extensions. | 已确认保留 |
| 10 | `core/remote_catalog.rs` + `pi refresh` | TS `ModelRuntime` 启动时/后台自动刷新远程模型目录（`pi.dev/api/models/providers/{provider}`，etag/304、4h TTL、models-store.json 缓存），无独立手动命令（交互模式模型选择器里后台刷新） | Rust 实现**有界子集**：`pi refresh [--force|--offline|--catalog-url]` 手动命令 + `remote_catalog.rs`（按 provider 拉取、解析三种目录格式、`ModelRegistry::upsert_models` 合并、models-store.json 持久化、fresh/304/404/失败保留缓存）。未做：启动/后台自动刷新、可用性检查、credential 同步（属 #16 ModelRuntime 其余部分，待排期） | 满足"手动刷新模型目录"的实际需求；自动刷新留待 #16 完整排期时补 | 已确认保留（有界子集） |
| 11 | `modes/acp/`（新增） | TS 原版无原生 ACP 支持（Zed 里靠第三方 `pi-acp` Node 适配器桥接 `--mode rpc`） | pi-rs 新增原生 ACP mode（`pi-cli --acp`），直接实现 `agent-client-protocol` 的 `Agent` trait，会话由 session task 持有 | 让 pi-coding-agent 可直接用于 Zed/JetBrains 等 ACP 编辑器，不依赖 Node 适配器。属于原版没有的新功能，非移植偏差 | 已确认保留 |
| 12 | `modes/acp/session.rs:create` | （无对应 TS 行为） | 无默认模型配置时回退到第一个内置模型，保证 session 可创建（客户端可后续通过 config options 切换模型） | ACP 客户端（Zed）通过 `session/config` 选项选模型，session 创建不应因未配置默认模型而失败 | **已回退**：改为对齐 TS 原版 `findInitialModel`（model-resolver.ts）——settings 默认模型要求有 auth；否则回退到第一个有 API key 的模型（`DEFAULT_MODEL_PER_PROVIDER` 优先）；一个都没有才创建无模型 session（prompt 报"没有选择模型"）。原实现"第一个内置模型"是 HashMap 随机顺序，且不检查 API key，导致随机选到无 key 的 provider |
| 13 | `modes/acp/agent.rs:load_session` / `session.rs:SessionRegistry` | （无对应 TS 行为） | 跨进程 session 持久化已实现：每个 ACP session 写入独立的 JSONL 文件 + `{sessions_dir}/acp/session-map.json` 记录 sessionId→文件/cwd 映射，`session/load` 可按 ID 在重启后恢复消息。已知约束：session map 假设同一时刻只有一个 ACP 进程写入（无并发锁） | 让 `session/load` / `session/list` 跨进程可用（对应 pi-acp 的 session-map.json 行为） | 已确认保留 |
| 14 | `core/mcp.rs`（新增，`mcp` feature 默认开启）+ `modes/acp/` | TS 原版无原生 MCP 客户端接入 | pi-rs 新增 MCP 客户端支持：ACP `session/new` / `session/load` 携带的 `mcpServers`（stdio / streamable-HTTP）会被连接、枚举工具并注入 session 的 `custom_tools`，工具调用转发回 MCP 服务器。SSE 传输未实现（capabilities 声明 sse=false）。工具集在 session 创建时固定，`prompt` 不再携带 mcpServers（本版本 ACP 规范如此） | 让 Zed 等 ACP 客户端能调用外部 MCP 服务器的工具 | 已确认保留 |

| 15 | llama.cpp router 集成 + Hugging Face 模型搜索/下载（v0.81.0 #f1a466b19/#3da591ab7） | TS 新增内置 llama.cpp router 支持：`/login` 连接设置、`/llama` HF 模型搜索与下载、显式加载/卸载与实时进度（`extensions/llama/client.ts` + `provider.ts` + `ui.ts`，1300+ 行） | 未实现 | 用户拍板：本地模型管理（llama.cpp/HF 下载）不在 pi-rs 范围；本地 LLM 场景已有 Ollama 自动发现（见 pi-ai DEVIATIONS #4）覆盖 | 已确认保留（范围外） |
| 16 | `mod.rs` / `agent_session.rs:ext_ctx` | TS RPC mode 创建完整 `ExtensionUIContext`（select/confirm/input/notify/setStatus/setWidget/setTitle/editor/set_editor_text），通过 `extension_ui_request` 事件与客户端交互，`pendingExtensionRequests` 跟踪响应 | Rust now wires the full UI context: `ExtensionUIContext` gained async `select`/`input` + fire-and-forget `set_widget`/`set_title`/`set_editor_text`; RPC mode's `create_rpc_ui_context` emits `extension_ui_request` and awaits `extension_ui_response` via the shared `pending_extension_requests` map (matching TS `createDialogPromise`). | **Reversed**: extension UI context is fully wired in RPC mode. | 已回退 (was 已确认保留) |
| 17 | `mod.rs` | TS 通过 `bindExtensions({ onError })` 输出 `{ type: "extension_error", extensionPath, event, error }` 事件 | Rust now supports it: `ErrorListener` is structured (`ExtensionError{extension_path,event,error}`), `bind_extensions` stores `on_error`, and RPC mode binds an `onError` that outputs `extension_error` events (matching TS `rebindSession`). | **Reversed**: extension_error events are emitted. | 已回退 (was 已确认保留) |
