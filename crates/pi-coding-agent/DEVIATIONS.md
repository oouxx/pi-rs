# DEVIATIONS.md — pi-coding-agent RPC Mode

This file documents intentional deviations from the TypeScript original
(`packages/coding-agent/src/modes/rpc/rpc-mode.ts`) in the Rust port.

| # | 位置 (ファイル:行/関数) | 原 TS 行为 | Rust 实际行为 | 修改原因 | 确认状态 |
|---|------------------------|-----------|--------------|---------|---------|
| 1 | `handler.rs:Prompt` | TS emits `success(id, "prompt")` via `preflightResult` callback after preflight succeeds, or `error(id, "prompt", msg)` on failure. | Rust emits `success(id, "prompt")` in the `AgentEnd` event listener (no separate preflight phase). | Rust's `AgentSession::prompt()` doesn't have a preflight callback mechanism. The success response is emitted when the agent run completes (AgentEnd event), which is functionally equivalent for the RPC client. | 已确认保留 |
| 2 | `handler.rs:NewSession` | TS calls `rebindSession()` after successful new session to re-subscribe events and re-bind extensions. | Rust does not rebind — the session reference remains valid after `new_session()`. | In the current Rust architecture, extensions are bound at construction time and the session is not replaced by `new_session()`. The session reference remains valid. | 已确认保留 |
| 3 | `handler.rs:Fork` | TS returns `{text: string, cancelled: boolean}` where `text` is the selected text from the fork result. | Rust returns `{text: "", cancelled: false}` — the `text` field is always empty. | Rust's `fork_session()` returns a path string, not a fork result with selected text. The `text` field is not available from the current API. | 已确认保留 |
| 4 | `handler.rs:SwitchSession` | TS calls `rebindSession()` after successful switch. | Rust does not rebind. | Same reason as #2 — session reference remains valid. | 已确认保留 |
| 5 | `handler.rs:GetCommands` | TS queries `extensionRunner.getRegisteredCommands()`, `promptTemplates`, and `resourceLoader.getSkills()`. | Rust now queries extension commands via `resolve_extension_commands(registry.commands())`, `prompt_templates()`, and `resource_loader().skills` — matching the TS order (extension → prompt → skill). | **Reversed**: extension commands are now included. `ResolvedCommand.source_info` changed from `Option<SourceInfo>` to `SourceInfo` to carry provenance. | 已回退 (was 已确认保留) |
| 6 | `mod.rs` | TS handles `extension_ui_response` type on stdin to resolve pending extension UI dialogs (select/confirm/input/editor). | Rust handles `extension_ui_response` type on stdin via `pending_extension_requests` map in `RpcHandlerState`. Extensions are now enabled in RPC mode (`enable_extensions: true`), matching TS behavior. | **Reversed**: extensions are now enabled in RPC mode. | 已回退 (was 已确认保留) |
| 7 | `handler.rs:Prompt` | TS passes `images` and `streamingBehavior` to `session.prompt()`. | Rust passes `images` and `streaming_behavior` through `PromptOptions`. | Functionally equivalent — the Rust `PromptOptions` struct supports both fields. | 已确认保留 |
| 8 | `handler.rs:Bash` | TS passes `excludeFromContext` to `session.executeBash()`. | Rust passes `exclude_from_context` through `execute_bash()` to `record_bash_result()`. | Implemented: `execute_bash()` now accepts `exclude_from_context: Option<bool>` and calls `record_bash_result()` internally, matching TS behavior. | 已确认保留 |
| 9 | `agent_session.rs:set_model` / `cycle_model` | TS `_emitModelSelect()` only calls `this._extensionRunner.emit(...)` — model_select is sent to extension runner only, NOT through session's `subscribe` mechanism | Rust was calling `self._emit(AgentSessionEvent::ModelSelect { ... })` which sends model_select to all session subscribers (including RPC mode's event listener) | TS only sends model_select to extension runner, not as a session event. RPC clients should not receive model_select events. Fixed by removing the `_emit` call, keeping only `dispatch_model_select` to extensions. | 已确认保留 |
