# PORTING_MISTAKES.md — pi-coding-agent RPC Mode

This file documents bugs found and fixed during the RPC mode alignment check.

| # | 位置 | 现象 | 根因模式 | 修复方式 |
|---|------|------|---------|---------|
| 1 | `handler.rs:Prompt` | Prompt handler returned `None` — RPC client never got a response for prompt commands. | Missing success/error response emission. TS emits response via `preflightResult` callback; Rust had no equivalent. | Added success response emission in `AgentEnd` event listener. |
| 2 | `handler.rs:Prompt` | `id` field was discarded (`id: _`), so prompt responses had no correlation ID. | Field ignored in pattern match. | Changed to use `id` for the response. |
| 3 | `handler.rs:Prompt` | `images` and `streaming_behavior` fields were discarded. | Fields ignored in pattern match. | Passed through to `PromptOptions`. |
| 4 | `handler.rs:AbortBash` | `AbortBash` called `session.abort()` instead of `session.abort_bash()`. | Wrong method called — TS has separate `abortBash()` and `abort()` methods. | Changed to `session.abort_bash()`. |
| 5 | `handler.rs:AbortRetry` | `AbortRetry` called `session.abort()` instead of `session.abort_retry()`. | Wrong method called — TS has separate `abortRetry()` and `abort()` methods. | Changed to `session.abort_retry()`. |
| 6 | `handler.rs:SetAutoRetry` | `set_auto_retry` was a no-op — returned success but didn't call `session.set_auto_retry_enabled()`. | Implementation missing. | Added call to `session.set_auto_retry_enabled()`. |
| 7 | `handler.rs:SetSteeringMode` | `set_steering_mode` was a no-op — returned success but didn't call `session.set_steering_mode()`. | Implementation missing. | Added call to `session.set_steering_mode()`. |
| 8 | `handler.rs:SetFollowUpMode` | `set_follow_up_mode` was a no-op — returned success but didn't call `session.set_follow_up_mode()`. | Implementation missing. | Added call to `session.set_follow_up_mode()`. |
| 9 | `handler.rs:GetState` | `model` field was a string (model ID) instead of a full model object. | Response format mismatch — TS returns full `Model<any>` object. | Changed to return `RpcModelInfo` with id, provider, name, api. |
| 10 | `handler.rs:SetModel` | Response returned `{id, provider}` instead of full model object. | Response format mismatch. | Changed to return full model via `serde_json::to_value(&m)`. |
| 11 | `handler.rs:CycleModel` | Response always returned `{model: {id, provider}}` — never `null`. | Response format mismatch — TS returns `{model, thinkingLevel, isScoped} | null`. | Changed to use `session.cycle_model()` which returns `Option<(Model, Option<ThinkingLevel>, bool)>`. |
| 12 | `handler.rs:CycleThinkingLevel` | Response always returned `{level}` — never `null`. | Response format mismatch — TS returns `{level} | null`. | Changed to use `session.cycle_thinking_level()` which returns `Option<String>`. |
| 13 | `handler.rs:SetSessionName` | No validation — empty names were accepted. | Missing validation — TS validates `name.trim()` is non-empty. | Added validation and error response for empty names. |
| 14 | `handler.rs:GetEntries` | Returned `{id, type: "entry"}` stubs instead of real `SessionEntry` objects. | Wrong data returned — used `session_entry_id()` helper instead of serializing entries directly. | Changed to serialize `SessionEntry` via `serde_json::to_value()`. |
| 15 | `handler.rs:GetTree` | Returned flat entry stubs instead of tree structure. | Wrong data returned — didn't use `session.get_tree()`. | Changed to use `session.get_session_manager().get_tree()` and serialize recursively. |
| 16 | `handler.rs:GetForkMessages` | Returned full `AgentMessage::User` serialized instead of `{entryId, text}` format. | Response format mismatch. | Changed to use `session.get_user_messages_for_forking()` which returns `Vec<(String, String)>`. |
| 17 | `handler.rs:Clone` | Response returned `{path, cancelled}` instead of `{cancelled}`. | Response format mismatch — TS returns `{cancelled}`. | Changed to return `{cancelled}` only. |
| 18 | `handler.rs:Fork` | Response returned `{path, cancelled}` instead of `{text, cancelled}`. | Response format mismatch — TS returns `{text, cancelled}`. | Changed to return `{text, cancelled}` (text is empty string as noted in DEVIATIONS.md). |
| 19 | `rpc_types.rs` | `RpcCommand` enum was missing `ExportHtml` variant. | Missing variant — TS has `export_html` in `RpcCommand` type. | Added `ExportHtml` variant. |
| 20 | `mod.rs` | Event channel and direct stdout writes could interleave, corrupting JSONL protocol. | Two writers to stdout — spawned task for events and `print!()` for responses. | Changed to single `mpsc::UnboundedSender<String>` channel for all stdout writes. |
| 21 | `mod.rs` | Signal handler took ownership of session via `session_for_signal`, then main loop also used session — race condition. | Double-use of session between signal handler and main loop. | Changed to use `AtomicBool` flag for shutdown signaling; main loop handles cleanup. |
